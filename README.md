## $5 和 $6 差的不只是 1 美元

第三方在东京机房对三档入门套餐做过一轮单次测试（Ubuntu 24.04，2026 年 9 月）。$5 的 Regular 用普通 SSD，顺序写大约 308 MiB/s；$6 的 NVMe 档在 1017 到 1816 MiB/s 之间。这个差距不是跑分好看不好看的问题，装个 WordPress、拉一批小文件、数据库做随机读写，体感差别很明显。

同样是 $6，High Frequency 和 High Performance 之间该怎么挑？测试里 AMD 平台的 High Performance 在 CPU 得分上是 High Frequency 的 3.68 倍，顺序写高 1.79 倍，4K 随机读两者都在 10.7 万 IOPS 上下，差距落在单次测试的误差里。也就是说，同价位下 High Performance 的 AMD 档基本全面压过 High Frequency，High Frequency 剩下的优势是入门档给的磁盘更大、内存档位起步更高。

结论可以下得直接一些：预算卡在 $6，选 High Performance 的 AMD 档；除非你确实需要更大的系统盘，或者对 Intel 平台有偏好（High Performance 也有同价的 Intel Xeon 版本）。High Frequency 更适合那些明确知道自己在为高主频付钱的场景，比如某些 PHP 脚本、游戏逻辑这类吃单核的应用。

至于 Optimized 和 VX1，专用 vCPU 的意义是 CPU 核心不被邻居争用。共享型实例在晚高峰被同宿主机的高负载用户拖慢，是 VPS 的常态，不介意这点就没必要多花四五倍的钱。生产库、对延迟抖动敏感的计费系统，这钱花得值。

## 机房怎么选：同一个 Vultr，三条线路三种体验

Vultr 全球有 30 个以上数据中心（不同来源口径为“19 个国家 32 座城市”或“30+”，以官网为准），亚太区有东京、大阪、首尔、新加坡、孟买、德里、班加罗尔七个节点。国内用户真正会考虑的是前四个，它们的线路完全不是一回事。

### 东京（NTT）：联通的主场，电信的雷区

测试地址 `hnd-jp-ping.vultr.com`，本地直接 ping 就能看到自己的延迟。上海到东京物理距离约 1700 公里，理论延迟 40–80ms，实测上海地区落在 40–100ms 区间。

分运营商看差别很大。联通是东京最理想的受众，华东部分节点实测 40–60ms，速度快、丢包少。电信白天还能接受，晚高峰（20:00–23:00）NTT 线路拥堵，丢包率能到 10%–20%，有电信用户夜间实测下行只剩 100KB/s 左右。移动比电信略好，晚高峰同样可能丢包。三家在东京的表现排序是联通 > 移动 > 电信。

### 首尔（KT/SK）：东京的备选

延迟和东京接近，部分地区甚至更好，电信联通都有一定优化。测试地址 `sel-kor-ping.vultr.com`（另有 `141.164.34.61`），官方还提供 100MB 和 1GB 的测速包。东京晚高峰卡得难受的话，首尔值得开一台对比，反正按小时计费。

### 新加坡（GTT）：给东南亚和港台用，不是给大陆用

测试地址 `sgp-sg-ping.vultr.com`。机房本地带宽很足，峰值下行能到 3000+ Mbit/s，上行 1700 Mbit/s 以上，硬件条件不差。问题出在回程：联通平均约 163ms，电信、移动都在 250ms 上下，西部电信能到 300ms 以上；电信联通去程走 NTT 绕日本，电信部分节点回程甚至是“新加坡 → 美国 → 荷兰 → 中国大陆”，移动部分节点也走美国中转。丢包率约 12%，晚高峰体验明显下滑。

它的价值在别处：到香港约 33ms、台北约 43ms，到马来西亚、泰国、印尼、菲律宾延迟极低。做东南亚跨境电商、需要新加坡原生 IP 跑广告投放或 TikTok 运营的，这个节点合适；面向大陆用户的站放这里就是自找麻烦。

### 大阪和美西

大阪和东京共享 NTT 线路，特性类似，实测对比一下再定。美西方向，网上流传的西雅图测速数据大多出自 2020 年，三网 200ms 出头那种数字放到今天只能当历史参考，不能当现状。方向上可以记一句：电信用户如果东京晚高峰撑不住，洛杉矶、硅谷是常见的替代方向，具体表现仍需自己开一台测。

## 账单上最容易多付钱的三处

### 672 小时封顶，这条对你有利

所有计算实例按小时计费，同时有月账单上限，每月按 672 小时（约 28 天）封顶。一台机器整月不停，也只按 672 小时收，不会按 31 天的 744 小时算。VX1 是例外，按实际使用小时数计费，不封顶。

### 关机不等于停止计费

关机之后 IP、内存、CPU 资源仍然保留着，账单继续走，必须执行销毁（Destroy）才停。这条在论坛里被反复踩，尤其是试用完忘了删机器、或者以为关机就没事的人。不用了直接销毁，需要时再开，反正按小时计。

### 流量额度是按小时攒出来的

每个套餐含固定的月度出站流量，入站免费，超额部分统一按 $0.01/GB 计费（2023 年起改成账户级流量池和全球统一费率）。$5 套餐含 1TB，$6 的 High Performance 含 2TB，$6 起的 High Frequency 含 1TB。

容易被忽略的是额度的发放方式：每台运行中的实例按小时把当月额度的一小份（月额度 ÷ 672）累加进可用池，超出当前已累积的额度就开始计费。月初头几天跑一波大流量，额度还没攒够，超额会比预想中来得早。

算一笔账：$5 套餐含 1TB，某月出站 3TB，超额 2TB 约 $20，账单约 $25。这个数字比很多人印象里“亚洲流量贵到离谱”要低，早期按区域计价时亚洲、澳洲是 $0.025–$0.05/GB，现在统一到 $0.01/GB 了。

比流量更容易多花钱的是几项附加项：自动备份加收 20%，快照按 $0.05/GB/月计费，DDoS 高级防护 $10/月，块存储 NVMe $0.10/GB/月（100GB 就是每月多 $10），托管数据库 $15/月起。这些默认不开，但手滑点一下，账单就不是 $5 了。

## 哪些人用了会后悔

**主要用户在中国大陆、对速度有要求的站点**。Vultr 的亚洲节点走的是普通 BGP、NTT、GTT 线路，没有 CN2 GIA 这类针对大陆优化的专线。要国内访问快，国内云厂商的轻量服务器或者专门做优化线路的服务商更合适。

**电信用户跑东京的生产环境**。晚高峰 10%–20% 的丢包率，对网页浏览是卡顿，对 API 和数据库连接就是事故。换首尔或美西方向测一轮再定。

**需要人工客服的人**。Vultr 的技术支持只有工单，没有在线客服，复杂问题基本靠自己。指望有人手把手带你迁站的，用哪家都不该选这种自助型平台。

**把快照当唯一备份的人**。快照存在同一个数据中心，块级恢复不灵活，还按 $0.05/GB/月收费。异地文件级备份和数据库备份得自己做。

横向看，Vultr 的 $5–$6 起步价与 DigitalOcean、Linode 基本持平，介于廉价 VPS 和 AWS、GCP 的标准实例之间。流量政策上，阿里云、腾讯云轻量走的是“大流量包”路线，Hetzner、OVH 以大流量额度著称，Vultr 是“含固定额度 + 超额按量”，跑大流量业务前先算清楚。

## 下单前的五步测试法

按小时计费的好处是试错成本几乎为零，开一台跑测试再销毁，几美分的事。顺序可以这样走：

1. 用测试地址 ping 一遍：东京 `hnd-jp-ping.vultr.com`、首尔 `sel-kor-ping.vultr.com`、新加坡 `sgp-sg-ping.vultr.com`。延迟高于 200ms 的机房直接排除。
2. 到官网的 Network Speed Tests 页面下载 100MB 或 1GB 的测速文件，看实际带宽，别只看 ping。
3. 注册后用赠金开一台最低配，跑一轮 YABS 之类的脚本，摸清 CPU 和磁盘的真实水平。
4. 晚高峰（20:00–23:00）单独再测一次丢包率，这一步最容易被跳过，也最能区分机房好坏。
5. 按实测结果选机房和套餐，再正式下单或充值。
